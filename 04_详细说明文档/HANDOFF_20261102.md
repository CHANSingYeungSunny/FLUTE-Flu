## 4. THE PEAK-SKILL RESULT (the counter-intuitive finding worth publishing)

Criterion (Kramer & Shaman 2019): **PTE ≤ 1 week AND PIE ≤ 25 %**, per fixed step
0/1/2/3 = 1/2/3/4 weeks ahead, on ILITOTAL de-normalised to patient counts.

| Model | passes / 16 | PTE (best) | PIE (best) |
|---|---|---|---|
| **NLinear** | **4 / 16** | 1.677 wk | 9.477 % |
| PatchTST | 0 / 16 | **1.240 wk** (best timing) | 32.755 % |
| every other arm | 0 / 16 | — | — |

**MSE champion ≠ peak champion.** PatchTST wins accuracy but fails calibration; NLinear is the
only arm that satisfies the epidemiological criterion, and only at step 0. This is the strongest
original contribution in the current dataset.

## 6. METHODOLOGY DECISIONS A REVIEWER WILL ASK ABOUT

1. **Why the `(W//16)*16` windows?** Because MIFlu's own loader uses `drop_last=True` with
   batch 16. Scoring on 170 windows for everyone else and 160/144/144/128 for MIFlu would give
   MIFlu an easier test set — the discarded 10/14/2/6 windows are **~1.41× harder** (measured
   1.3929–1.4423 across four L24 seeds). Using the same cropped windows for all 17 arms is the
   only like-for-like choice.
2. **Why 7-variable z-space MSE for the reproduction but ILITOTAL PTE/PIE for the benchmark?**
   The 7-variable aggregate is a *loss*, not a series — it cannot be de-normalised (OT train mean
   493,629 vs %WEIGHTED ILI 1.74). PTE/PIE require a single interpretable series, so they use
   ILITOTAL only.
3. **Why validation-based checkpoint selection?** The author's code selects on the **test** set
   (`main_ILI_lora.py` L211/L225) — that is leakage. We select on validation and disclose the
   deviation.
4. **Why is MIFlu excluded from paired sign-flip tests in the original design?** It is not, any
   more: after the seed amendment all models share 42/43/44, so paired tests are valid for every
   model. The earlier exclusion existed only because the seed sets did not match.
5. **Train/validation/test split**: 70/10/20 in time order with a leakage guard (minimum
   test target-start index 773 under `containment=strict`), matching the author's proportions.

## 9. PUBLISHABILITY ASSESSMENT (honest)

**Is what exists enough for a top-tier journal, plus an innovation on top? No, not yet — and
the gap is not the innovation.**

What we have is a *solid reproduction + a rich benchmark + one genuinely interesting finding*
(MSE champion ≠ peak champion) *+ a new evaluation axis* (LLM encoders as frozen feature
extractors for epidemiological forecasting). That is a good **benchmark/evaluation paper**.

What a JBHI-or-above reviewer will still demand:
1. **Rolling-origin evaluation.** A single fixed split is the classic objection. This is the
   single largest hole and it costs 120–300 A100-hours.
2. **A stated contribution stronger than "we benchmarked".** "We add LLM encoders" is a
   dimension, not yet a claim. The defensible claim is: *frozen LLM representations do/do not
   improve epidemiological forecasting, and where the accuracy–calibration trade-off sits.* The
   numbers to support it now exist (11 arms) — what is missing is the analysis and the argument.
3. **The ablation that cannot move a number.** `--no-text` being bit-identical is a real
   methodological finding, but it must be presented as such, not as an ablation.
4. **Honest reproduction framing.** +4.5 % with a sign crossover is publishable *as a
   reproduction study*; it is not publishable as an improvement.

**Recommended target order**: IEEE JBHI (the original venue — a reproduction plus extension is a
natural fit) → *Journal of Biomedical Informatics* → *PLOS Digital Health* → a benchmarking
track at a conference (NeurIPS D&B, or ACM CHIL) if the contribution is framed as a benchmark.
