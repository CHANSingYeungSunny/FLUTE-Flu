# TEXT PATH RESOLUTION — P0 矛盾的解决

生成时间：2026-10-06　　目标：解决 A0 GPU 重放 与 Stage-2 CPU 探针 关于「作者发布代码的文本通路是否生效」的相反结论。

---

## 0. 结论（一句话）

**矛盾已解决：作者发布代码的文本 CONTENT 对预测的影响严格为零。**
A0 GPU 观察到的「multimodal=1 更好」**不是文本效应**，而是 `multimodal` 开关改变**序列长度**（42 → 359）后，在**训练期间**改变 dropout 随机数消耗所导致的优化轨迹差异。

## 2. 为什么之前的对比是无效的（这是矛盾的关键）

A0 GPU 证据（作业 587091 / 587068）比较的是：

```
--multimodal 0  → 序列长度 42   → Test MSE 0.9685
--multimodal 1  → 序列长度 359  → Test MSE 0.8581
```

**这个对比不能隔离文本内容**，因为它同时改变了：

1. 序列长度（42 vs 359）→ GPT-2 注意力计算的规模
2. **训练期间的 dropout 随机数消耗** → 每个 step 的 dropout mask 全部不同
3. 因此最终的具体权重不同（不同的随机优化轨迹）

**这不是「文本带来的增益」，是「换了一组随机数带来的增益」。**

### 本轮新增的实证（flag control）

在**固定权重、eval 模式、关闭 dropout** 下重跑同一对比：

| 对比 | 序列长度 | `max\|Δpred\|` | 解读 |
|---|---|---|---|
| `multimodal=0` vs `multimodal=1` | 42 vs 359 | **2.384e-07** | ≈ float32 舍入量级（ε=1.19e-07），**数学上等价** |
| 等长不同内容文本替换 | 359 vs 359 | **0.000e+00** | 严格零 |

**这正好验证了静态因果掩码分析**：被保留下来的 42 个 patch 位置在序列中全部位于文本之前，GPT-2 的因果注意力使它们**无法**看到后面的文本；因此**数学上**输出必然相同，实测只剩 float32 累加次序造成的 2.4e-07 舍入差。

**所以 A0 的 0.9685 vs 0.8581 完全由训练期 dropout RNG 差异解释，与文本内容无关。**

## 3. 探针的检验力：positive control（证明「不是探针瞎了」）

零结果必须排除「探针根本没有检测能力」。为此加入**声明式算法修改**的阳性对照：把文本**前缀**到 patch 之前，并由预测头读取**文本之后**的 patch 位置（即恢复计划 §5 提到的 "prefix-text repair"）。

实现方式为**对发布 `forward` 源码做恰好两处文本替换后 `exec`**，并在 JSON 中记录完整 diff；若两处替换之一未能命中，脚本**直接中止**（拒绝在未修改的 forward 上跑对照）。

| 运行 | `max\|Δpred\|` | 判定 |
|---|---:|---|
| 发布实现（文本在后） | **0.000e+00** | 无影响 |
| **阳性对照（文本在前，声明式修改）** | **3.552e-05** | ✅ **检测到文本影响** |

**结论：探针**有能力**检测文本影响；发布路径上的严格零是**真实的零**，不是探针失灵。**

> 阳性对照的绝对值很小（3.55e-05），因为本轮使用**确定性随机初始化权重**（无 checkpoint）——A0 发布代码本身也不提供 checkpoint。这是**检出**，不是幅度声明。

## 4. 与 Stage-2 CPU 审计的关系

Stage-2（作业 587002）测得文本替换输出差 `0.000e+00`、文本梯度 `0.000e+00`。本轮用**完全不同的实现**（独立探针、等长内容替换、带阳性对照）得到**相同的结论**。

因此正确的表述是：

> **Stage-2 的 CPU 判定是对的；A0 的 GPU 判定是误读。**
> 作者发布代码的文本通路**确实惰性（inert）**。「GPU 与 CPU 结论矛盾」这一未决项应当**结案**，并修正 Stage-6 报告 §5.3 与恢复计划中「矛盾未解」的表述。

## 6. 补充（2026-10-06 新增）：**A2 修正实现的文本通路是「生效」的**

上面的判决只针对**作者发布代码**。但**基准比较用的是 A2**，所以必须单独验证 A2，否则「notext 与 miflu 的差异」是否真来自文本内容就无从谈起。

脚本 `probe_a2_text_path.py`（同一方法：固定权重、eval、等长不同内容替换），本地 CPU 运行，使用真实训练 checkpoint `hpc_results/checkpoints/best_miflu_L24.pth`。

| 项 | 值 |
|---|---|
| checkpoint 加载 | 106 个张量全部命中；`missing=12` |
| 那 12 个缺失键是什么 | `forecasting_llm.blocks.{0..5}.attn.{bias,masked_bias}` —— GPT-2 的**因果掩码 buffer**，**确定性常量、不可训练**。因此**加载的确实是训练后的权重**，不是随机初始化 |
| 文本形状 | L=24 与 L=60 两个 prompt **长度完全相同**（1552 字符 → `(1, 369, 768)`）→ **天然等长对照** |
| 三个变体形状是否一致 | ✅ 一致（`same_shape_all_variants = True`） |

| 对照 | `max\|Δpred\|` | 有差异的元素 |
|---|---:|---|
| **不同 prompt（等长）** | **59.6875** | **168 / 168（全部）** |
| 同行打乱（同多重集） | 6308.312 | 168 / 168 |
| 文本 embedding 梯度范数 | **7.13e+08** | — |
| **判决** | **`text_active`** | |

### 两个实现的正面对照

| 实现 | 文本通路结构 | 判决 | 依据 |
|---|---|---|---|
| **作者发布代码** `GPT4TS_lora.py` | 文本拼在 patch **之后**，因果注意力使其不可达 | **`text_inert`** | 等长替换 max\|Δ\| = **0.0**，文本梯度 = **0.0** |
| **A2 修正实现** `miflu_model.py` | 文本拼在 patch **之前**，读**尾部** patch 位置（L376 / L407） | **`text_active`** | 等长替换 max\|Δ\| = **59.7**，文本梯度 = **7.1e8** |

**结论**：
1. P0 矛盾的「作者代码」那一半，结论是**惰性**；
2. 而**基准所用的 A2 实现，文本通路确实生效** —— 因此 A2 中 `notext` 与 `miflu` 的对照**是真正的文本内容对照**，不是「换了序列长度」的伪对照；
3. 这两件事不矛盾，且必须**分别陈述**：**不得**用 A2 的 `text_active` 去替作者代码辩护，也**不得**用作者的 `text_inert` 去否定 A2 的机制实验。
