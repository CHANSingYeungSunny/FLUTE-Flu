## 0. 一句话结论

在作者 966 行数据、同一冻结协议下拟合的**八模型统一比较**中，**MIFlu 与 NLinear 这两个模型在 12 个配对格上完全不可分（t = −0.11，5/12 胜）**——也就是说，本轮最强的可核验结论是**加了文本的 MIFlu 没有超过最简单的线性基线**。去掉文本通路的控制组（no-text，1.922）数值上最好，且显著优于 NLinear（t = −2.28，11/12），但相对 MIFlu 的优势**未达显著**（t = −1.50），因此不能宣称「去掉文本更好」。三个 LLM 骨干（calf / qwen / timecma）在同一协议下**全部显著劣于** NLinear。**本轮不是对论文的复现判定**：A0（作者发布代码逐字重放）只做到「最小可执行诊断」，且它与 Stage 2 的 CPU 审计**就「作者代码的文本通路是否生效」得出相反结论，矛盾尚未定位**（见 §5.3）。

## 4. 关键判断

### 4.1 可确认的分组（不是连续排名）

配对证据支持把八模型分成四组，**组内不可分**：

| 组 | 模型 | average_MSE_4L | 证据 |
|---|---|---|---|
| A | MIFlu / NLinear | 2.042 / 2.050 | 组内**不可分**（t=−0.11，5/12） |
| B | DLinear | 2.348 | 显著劣于 A 组（MIFlu−DLinear t=−3.36；NLinear−DLinear t=−8.51） |
| C | TimeCMA-LLM | 2.670 | 显著劣于 B 组（DLinear−TimeCMA t=−6.84） |
| D | PatchTST / iTransformer | 3.920 / 3.985 | 组内不可分（t=−1.40），显著劣于 C 组（TimeCMA−PatchTST t=−21.65） |
| E | Qwen-Time-LLM / CaLF-LLM | 5.220 / 5.515 | 显著劣于 D 组 |

**no-text 不在这张表里**：它不是八模型之一，而是机制控制组（1.922）。它的位置由两条独立证据确定：显著优于 NLinear（t=−2.28，11/12），但相对 MIFlu 的优势**不显著**（t=−1.50，5/12）。

**这是本轮的核心可核验结论**：在同一协议下，**加了文本的 MIFlu 与最简单的 NLinear 线性模型无法区分**；而 no-text 的优势虽然存在但未达显著，不能据此宣称「去掉文本更好」。三个 LLM 骨干全部落在最差的两组（D / E）。

### 4.2 LLM 组整体落后（描述性，非推断性）

分组口径以 `recompute_eight.py` 中**写死并持久化**的定义为准（`recompute_verify.out` 打印的也是这一口径），即 **4 vs 4**：LLM 组 = `miflu / qwen_time_llm / calf_llm / timecma_llm`（MIFlu 的骨干是 GPT-2，计入 LLM），non-LLM 组 = `nlinear / dlinear / patchtst / itransformer`。

| 组 | 成员 | average_MSE_4L 均值 |
|---|---|---:|
| LLM（n=4） | miflu 2.0415 / timecma 2.6700 / qwen 5.2196 / calf 5.5153 | **3.861596** |
| non-LLM（n=4） | nlinear 2.0496 / dlinear 2.3478 / patchtst 3.9205 / itransformer 3.9847 | **3.075638** |

> 本报告初版曾按「LLM = 三个 `*_llm` 骨干」写成 3 vs 5（4.468288 / 2.868814）。两个数都对，但口径与证据文件不一致，已改为上表的 4 vs 4。若只需「纯 LLM 骨干」的对比，则为 4.468288（n=3）vs 2.868814（n=5）。**引用时必须写明用的是哪一套。**

**这是对两个预先指定集合的描述性比较，不是对「LLM 预测器」这一类别的推断性声明**——4 个 / 4 个固定实现不是随机样本，不支持任何关于 LLM 预测器总体的结论。三个纯 LLM 模型的 trainable 参数量（370,376 / 1,981,608 / 1,391,016）与 B-track 实测同量级，同协议下仍全部落后。

### 4.3 与 Stage 5（A2）结论一致，且更强

Stage 5 只比较了 3 个模型，结论是「MIFlu ≈ NLinear，文本通路无确认收益」。本轮把比较面扩大到八模型后：
- MIFlu ≈ NLinear 的结论**在更大背景下依然成立**（t=−0.11）；
- no-text 优于 NLinear（t=−2.28，11/12）这一点 Stage 5 因样本量不足未能确认，本轮确认了；但 no-text 相对 MIFlu 的优势仍不显著（t=−1.50），因此**「文本通路无收益」这一表述仍然成立，「去掉文本更好」则不成立**；
- 进一步发现 DLinear / TimeCMA 构成中间梯度，PatchTST / iTransformer / Qwen / CaLF 显著更差，说明**在 966 行、193 行 Test 的小样本区间预测设定下，模型容量并不带来收益**。

### 5.3 与 Stage 2 审计结论的关系（重要修正）

Stage 2 的 CPU 审计曾判定作者发布代码「文本通路惰性（text inert）」。**A0 的 GPU 诊断与该判定不一致，必须并列阅读、不得单取其一**：

- Stage 2（`a0_cpu_audit`，作业 587002，CPU）测得 text→output 差异恰为 `0.000e+00`、文本梯度范数恰为 `0.000e+00`；
- A0（作业 587091 / 587068，A100，GPU）测得 `multimodal=0` → MSE 0.9685，`multimodal=1` → MSE 0.8581，输出确实不同。

**两者的差异尚未定位，本报告不给出原因。** 已知的最可能候选（均未验证）：Stage 2 的探针注入点与作者真实前向路径不一致；或 CPU 与 GPU 走了不同的分支/精度路径。任何一者都需要单独实验确认。

因此，正确的表述是：**作者代码的文本通路在 GPU 上、作者 argparse 默认值下确实生效；但 Stage 2 的 CPU 探针未能复现这一效应，两者矛盾未解。** 无论哪一方成立，作者代码的**其他**实质缺陷独立成立（Test 集只覆盖 `feat_id=[0]`、Test 参与 checkpoint 选择、LoRA 从未应用、`freeze` 为 no-op、1 epoch 默认、PEFT 关闭）。Stage 2 报告 `implementation_audit.md` §8 与本报告 §5 应一并阅读。
