# D-windows 对旧实验的影响评估（仅陈述可证据化部分）

量化数据：`recovery/stage5/windows_impact_on_old_runs.json`（2026-09-25 实测）。

## 1. 事实一：Test 窗口未越界，但这不等于没有泄漏

实测：三个 profile × 四个 L，**Test 窗口的目标全部完整落在 Test 段内**（`test_targets_fully_in_test = true`）。

这**只证明评分窗口本身没有越界**，即已报告的 Test 分数不是由"目标跨出 Test 段"造成的错误计算。它**不能**证明选模过程没有接触 Test。

## 2. 事实二：验证目标进入 Test 段 —— 这是选模层面的 Test 信息泄漏

按旧规则（按目标起点归属划分），每个 L 有 **L−1 个验证窗口**的目标尾部进入 Test 段：

| L | 越界验证窗口数 | 验证目标步数中属于 Test 的比例（project_1025 / author_966） |
|---|---:|---|
| 24 | 23 | 11.2% / 11.7% |
| 36 | 35 | 17.0% / 17.9% |
| 48 | 47 | 22.8% / 24.0% |
| 60 | 59 | 28.6% / 30.1% |

由于 checkpoint 是按验证集 MSE 选择的，**这些 Test 行参与了 checkpoint 选择**。因此就"Test 只评估一次、且在选模之后"这一协议而言，这些运行存在**选模层面的 Test 信息泄漏**。这一点如实记录，不作淡化。

**不推断方向**：该泄漏对被选模型在 Test 上得分的影响方向（更好还是更差）取决于模型对这些尾部行的拟合行为，**没有证据支持任何单向判断**，因此不作"必然使模型显得更好"或"因此不会改变结论"的推断。

## 3. 事实三：另有一类独立影响 —— 训练目标跨入验证集

旧规则下，训练窗口的目标同样可能跨进验证段（对称问题）。这类影响属于**训练阶段接触验证数据**，与第 2 节的选模泄漏是**两个不同的问题**，不合并，也不把全部问题归结为验证选模。

## 5. 旧结果的处置

- **保留**全部旧结果与其冻结证据，不删除、不重跑（除非导师另行要求）。
- **限定证据用途**：旧结果可用于说明"在旧窗口规则下得到的数值"与流程性事实；**不得**用于推断排名反转是否发生，也不得据这些数字宣布"反转"或"不反转"。
- 引用旧结果时必须标注其窗口规则为 `legacy target-start rule`，并注明存在 §2/§3 两类影响。
- 本轮 A2 使用 `--containment strict`，两类影响均被消除；A2 的结论**不与旧结果拼接排名**。

## 6. 本轮新增的隔离措施（防止同类问题重现）

- 训练阶段设 `DEFER_TEST=1`：Test loader 不被评估、预测导出被跳过 ⇒ 36 次拟合期间**不存在任何 Test 分数**；
- 全部 checkpoint 用验证集选定并锁定后，才由独立评分入口统一评分。
