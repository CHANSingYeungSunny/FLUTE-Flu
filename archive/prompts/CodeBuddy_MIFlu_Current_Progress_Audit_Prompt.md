## 四、核对实际代码行为及评分有效性

检查实际入口到 loader/model/evaluator 的调用链，而不仅是某个文件里存在相关函数。结合已有运行证据及必要的小型确定性检查，核对：
- multimodal 与 PEFT/LoRA 是否真的启用；实际 trainable parameters、层数及预训练 revision。
- 文本是否影响预测：相同长度、位置、权重与时序输入，eval 模式关闭 dropout 后替换文本；必要时检查文本梯度。先证明输入 embedding 确实改变。
- Test 是 feature 0 还是全部七变量；保存预测的 shape 和实际 `(origin, lead, variable)` 覆盖。
- 是否每 epoch 查看 Test，是否用 Test 选择权重；修正版是否使用 validation 选择并保存正确 checkpoint。
- `drop_last`、shuffle、缺失/失败样本及聚合权重是否影响实际评分范围。
- 训练、validation、Test 的完整预测目标是否落在各自 split 内；scaler 和 prompt 统计是否仅用许可的信息。
- Seasonal Naive 在 lead >52 时是否偷读 origin 后的真实观测；52/53 周与缺口处理是否明确。

原作者数据候选 split 为 676/97/193，在 T=104、完整目标包含规则下，L=24/36/48/60 的 train/val/Test origins 候选分别为 549/74/170、537/62/158、525/50/146、513/38/134。用真实代码核实，不把修正版的窗口契约强加给 A0 再宣称“原版重放”。

July 数据的 19 周缺口、week 53、窗口计数和历史修正必须按实际日历/代码确认；不能把旧计划中的初步推断当作当前结论。
