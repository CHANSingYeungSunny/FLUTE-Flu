## SSH 调用「卡住」根因分析（本机 Windows → burgundy HPC）
**症状**：多轮 `ssh sychan552@burgundy.hpc.cityu.edu.hk '<cmd>'` 无输出、看似挂死，用户手动取消。

**根因（按证据强度）**：
1. **缺 `-o BatchMode=yes` → 卡在不可见密码提示**。无 TTY 环境下 OpenSSH 会等 keyboard-interactive/password 输入，零输出、永不返回。铁证：备用 IP `144.214.138.99` 那次已把主机密钥写进 known_hosts（TCP+SSH 握手成功），随后静默挂住 = 典型密码提示挂起。
2. **连通性间歇性**。00:10:09 有一次成功（`hpclogin02` + date，说明公钥认证当时可用）；其后全部失败 → 与 9/15 记录的「连接超时」同类，非永久失效。
3. **`timeout N` 包装在 Git Bash(MSYS) 下不可靠**：带 `timeout` 的调用即使该报错也返回空文件。改用 `BatchMode=yes` + `ConnectTimeout` 让 ssh 自己快速失败。
4. **工具对 Git Bash 的 stdout 捕获不可靠** → 必须 `> /c/Users/Asus/<file>.txt 2>&1` 再 `read_file`。

**本机 SSH 环境事实（已实测）**：
- `~/.ssh/` 有 `id_ed25519`(419B) + `id_ed25519.pub` + `config` + `known_hosts`。
- `ssh-add -l` → **无 ssh-agent 运行**（"Could not open a connection to your authentication agent"）。
- `ssh -V` = `OpenSSH_9.9p1, OpenSSL 3.2.4`（`/usr/bin/ssh`，Git Bash 自带）。
- `~/.ssh/config` **只有** `region-9.autodl.pro` 与 `cityu` 两个 Host，**无 `Host *`** → 用 FQDN 直连时 config 不生效，不会被强制 keyboard-interactive。
- 注意 `id_ed25519` 权限显示为 `644`（OpenSSH 通常会拒绝过宽的私钥）；但 00:10 那次认证确实成功，故暂非主因，若复发应 `chmod 600`。

**PowerShell → Git Bash 传参的坑（必守）**：
- 外层用**双引号**，远程命令用**内层单引号**；反之外层单引号+内层双引号会被撕开。
- 禁止 `$(...)`（PowerShell 当子表达式展开）、禁止裸 `2>/dev/null`（被 PowerShell 当重定向 → `Out-File C:\dev\null` 报错）。
- 输出路径**不能含空格**（`FYP code` 会被拆参导致 `syntax error: unexpected end of file`）→ 写 `/c/Users/Asus/xxx.txt`。

**唯一可靠的调用范式**：
```
& 'c:\Program Files\Git\bin\bash.exe' -c "ssh -o ConnectTimeout=10 -o BatchMode=yes sychan552@burgundy.hpc.cityu.edu.hk 'date' > /c/Users/Asus/probe.txt 2>&1"
```
然后 `read_file C:\Users\Asus\probe.txt`。永不挂死（BatchMode 失败即退）。
