## 2. Template-selector deep-link forensics — `404` vs `418`

Exact URL: `https://template-selector.ieee.org/secure/templateSelector/publicationType`

The 2026-11-06 research note described "`404` with browser UA, **`418` with python-requests UA** (F5/CloudFront WAF bot block; reproducible 8/8)". Live re-verification **refines** this: the `418` is **not** triggered by the UA string alone; it requires the full python-requests *default header profile* (and is client-profile / TLS-fingerprint dependent).

| Client profile (observed 2026-11-06) | Status code | Reproducibility |
|---|---|---|
| `curl` with Chrome browser UA | `404` | 8/8 |
| `curl -A "python-requests/2.31.0"` (UA string only) | `404` | 8/8 |
| `curl -A "python-requests/2.31.0"` + `Accept: */*` + `Accept-Encoding: gzip, deflate, br` + `Connection: keep-alive` (full pyreq default headers) | **`418`** | **8/8** |
| Chrome UA + `Accept-Encoding: gzip, deflate, br` only | `404` | 1/1 |
| `python-requests/2.31.0` UA + `Connection: keep-alive` only | `418` | 1/1 |
| Native Python 3.13 `urllib` with the same nominal pyreq headers | `404` | 1/1 |

**Conclusion (required by TASK 5):** the `418` is a **UA/header-profile-dependent WAF bot-block response**, **not** evidence that the page/resource is missing and **not** a successful template download. The same URL answers `404` to a browser-like client and `418` to a bot-like client. `418` ≠ a missing page; it is the WAF refusing a machine client. `requests` was not installed (`ModuleNotFoundError: No module named 'requests'`), so the original python-requests client could not be run verbatim; the `418` was reproduced via curl with pyreq's default header set.

## 3. `/api/ieee-template-selector` — two-hop `302` → `502`

- Direct: `curl -s -o /dev/null -w "%{http_code}" https://template-selector.ieee.org/api/ieee-template-selector` → `302` (6/6 reproducible).
- Redirect target (observed via `%{redirect_url}`): `http://tselpav21.awsi.ieee.org:8001/ieee-template-selector/`.
- Following it: `curl -L ... -w "final_code=%{http_code} num_redirects=%{num_redirects}"` → `final_code=502 num_redirects=1`.
- So the earlier note's `502` is the **final** status after one `302` redirect; the direct status is `302`. Both were observed; neither yields a template file.
